# HITL 계획 — 발송 전 사람 승인

> 상태: APPROVED (2026-11-10 "구현 실행해줘") · 디스코드 검토 + GitHub Actions, 서버 없음

## 왜

지금 파이프라인은 `verify`에서 LLM이 원문과 대조해 틀린 요약을 빼고 예비 기사로 채운 뒤, `publish`가 Discord로 바로 보낸다.
검수 LLM도 100%가 아니라서, 검수를 통과한 오류는 그대로 구독자에게 나간다. Discord로 나간 메시지는 되돌릴 수 없다.

## 멈추는 자리

```
collect → select → report(팬아웃) → verify → [approve] → publish
```

- 만드는 일(`report`·`verify`)과 보내는 일(`publish`) 사이에 승인 노드 `approve`를 둔다.
- `approve` 안에서는 `interrupt` 전에 바깥으로 나가는 동작(알림·발송)을 하지 않는다. 재개할 때 노드가 처음부터 다시 실행되기 때문이다. 알림이 필요하면 별도 노드로 뺀다.

## 승인 단위

- **호 단위**: `thread_id` = 발행 날짜(예: `2026-11-10`).
- 하루치 기사 중 **하나라도** 기준에 걸리면 그 호의 발송을 멈춘다. 걸린 기사가 없으면 사람을 거치지 않고 그대로 보낸다.
- 승인 화면에는 걸린 기사를 강조해서 보여 준다.

## 멈춤 기준

| # | 기준 | 계산 방식 | 대비하는 위험 |
|---|------|-----------|---------------|
| ① | 원문에 없는 수치 | `headline`·`summary`에서 뽑은 숫자가 원문 `body`에 없으면 멈춤 (쉼표 제거 후 비교, `40대` 같은 독자 표현은 제외) | LLM 검수를 통과한 환각 수치 |
| ② | 건강·의학 조언 | `headline`·`summary`에 건강 키워드가 있으면 멈춤 | 사실은 맞아도 독자가 따라 하면 위험한 조언 |

②의 키워드: `콜레스테롤 혈압 혈당 질환 효능 복용 의사 피부과 통증 약물 보충제 처방`

- 2026-11-10 결정: `부상`·`치료`는 뺐다. 부상 예방·치료 기사는 통과시킨다. 질환 치료(예: 고혈압 치료)는 `혈압`·`질환`·`처방` 같은 다른 키워드가 계속 잡는다.

**자동으로 나가도 되는 건**: 숫자가 원문과 일치하고 건강 조언이 아닌 기사(옷·장비·일반 운동 팁 등). 이미 LLM 검수를 통과했고, 틀려도 독자가 입는 피해가 작다.

### 첫 관찰 (지난 3호, 요약 29건)

- "숫자가 있으면 멈춤"은 29건 중 20건이 걸려 헛멈춤이 너무 많다. 그래서 "원문에 없는 숫자"로 좁혔다.
- ②는 29건 중 3건이 걸렸다. `콜레스테롤 식습관`은 멈춰야 하는 건이고, `트레일 러닝 팁(부상)`은 헛멈춤일 가능성이 크다. 스포츠 파트 소개 자체에 "부상 예방"이 들어 있다.
- ①은 사본(`output/`·`issues/`)에 원문이 없어 아직 재지 못했다.

## 검증 방법 (교안 3장)

1. 원문까지 담은 기사 샘플을 모은다 (`scripts/hitl_samples.py` → `store/hitl/`, 본문 저작권 때문에 저장소에 올리지 않는다).
2. 기사마다 "사람이 봐야 하나"를 사람이 직접 표시한다 (정답).
3. 여러 기준 변형으로 개입률 · 놓침 · 헛멈춤을 센다 (`scripts/hitl_compare.py`).
4. 놓침과 헛멈춤 중 어느 쪽이 비싼지 따져 최종 기준을 고른다.

## 승인 화면과 응답 (교안 4장)

- 보여 줄 것: 기사 원문 발췌와 링크 · 요약 · 멈춘 이유(어느 숫자가 원문에 없는지, 어느 건강 키워드인지) · 통과시키면 일어나는 일("N건이 구독 채널로 발송됩니다")
- 응답: 승인 / 기사 빼고 승인 / 문구 수정 후 승인 / 발송 보류
- 체크포인터는 `SqliteSaver` (Actions 실행이 끝나도 대기 건이 남아야 한다)
- 미처리 규칙: 당일 정오(KST) 이후 첫 확인 실행까지 응답이 없으면 **걸린 기사만 빼고 발송** (기본값, 바꿀 수 있음)

## 구현 설계 (서버 없음 · 디스코드 검토)

비유: Actions는 아침에 잠깐 출근하는 직원이고, 멈춘 지점은 자물쇠 채운 서랍(암호화 파일)에 넣어 저장소에 둔다. 다음 직원이 서랍을 열어 이어 간다.

```
[daily.yml 07:30]  collect → select → report → verify → approve ─ 걸린 것 없음 → publish (공개 채널)
                                                          └ 걸림 → interrupt(review)
                     → 봇이 비공개 #검토 채널에 카드 + 스레드 + @멘션
                     → 체크포인트를 암호화해 store/checkpoints.enc 로 커밋, store/reviews.jsonl 에 대기 표시
[사람]  카드에 ✅ 승인 · ➖ 걸린 기사 빼고 · ⏸️ 보류 반응, 또는 스레드 답글
        (`승인` · `빼고 1,2` · `보류: 사유` · `수정 1: 새 요약` · `제목 1: 새 제목`)
        Streamlit 화면에서 응답하면 같은 형식의 답글을 스레드에 대신 단다
[review.yml 08:00~12:30, 30분마다]  run.py --check
        → 내 사용자 ID의 응답만 읽어 Decision → Command(resume=Decision) → publish
        → 정오 이후인데 응답이 없으면 걸린 기사만 빼고 발송
```

| 파일 | 역할 |
|------|------|
| `hitl.py` | 기준 · `Decision` · 답글 문법(`parse_reply`/`reply_text`) · 반응→응답 · 정오 규칙 |
| `graph.py` | `approve` 노드(interrupt 전 외부 동작 없음) · 보류면 `publish`가 보내지 않음 · `run`/`resume`에 체크포인터 |
| `hitl_store.py` | SQLite 체크포인트 암호화 저장·복원(Fernet), `reviews.jsonl` |
| `discord_review.py` | 봇 REST 호출만 (카드·반응·스레드·읽기·답글). 봇을 켜 둘 필요 없음 |
| `run.py` | 매일 실행에 승인 대기 처리, `--check` 확인 모드 |
| `.github/workflows/review.yml` | 30분 확인 실행 (같은 concurrency 그룹) |
| `app.py` | 실제 대기 건 보기 + 응답을 디스코드 답글로 남기기 (샘플 모드도 유지) |

비밀값(저장소에 올리지 않음, `.env`와 Actions Secrets에만): `DISCORD_BOT_TOKEN`, `DISCORD_REVIEW_CHANNEL_ID`, `DISCORD_REVIEWER_ID`, `HITL_STATE_KEY`.
