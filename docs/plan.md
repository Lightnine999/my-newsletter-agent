# 진행 계획 (1부 ~ 7부)

> 기준 문서: [PRD.md](../PRD.md) · 소스: [sources.md](sources.md) · 원본 명세: `sources-master.docx` · 교재: `D00_뉴스레터_노드_완전판.html`
> 원칙: ai-newsletter-agent에서 이미 동작하는 뼈대를 가져오고, 주제에 맞게 바뀌는 부분(파트·10건 배분·소스·기준)만 고쳐요.

## 준비물

- Python과 LangGraph 기초 (`StateGraph`, 노드, 엣지)
- OpenAI API 키 · 모델 `gpt-4.1-mini`

- 라이브러리: `langgraph` `feedparser` `requests` `trafilatura` `openai` `pydantic` (+ `python-dotenv` `pyyaml`)

## 준비 단계에서 확인한 것 (다음 단계 입력)

- 17개 피드 24시간 60건. 화장품 쓸 만한 후보는 4건 남짓 → 10건 배분 규칙의 ③(부족분 재배분)이 자주 쓰일 거예요.
- 뺀 곳 재점검: GQ 코리아·Men's Health AU 복구, Gentleman's Journal·Racquet 보류, AskMen은 AI 에이전트 금지라 제외.
- GQ 코리아 전체 피드는 최신 10건(반나절치)만 줘서 카테고리 피드를 같이 읽어요. 07:30 한 번 실행으로 놓치는 글이 없는지 2부에서 확인해요.
- 원문 자체가 틀린 경우가 있었어요(국내 기사의 LDL·HDL 뒤바뀜). verify 기준에 넣었어요.

## 2부에서 확인한 것 (3부 입력)

- 실측(2026-10-29 16:50): 60건 = sports 29 · mixed 19 · menswear 7 · grooming 5. 응답 없는 소스 0곳.
- 같은 글이 전체 피드와 카테고리 피드에 함께 있으면 한 건만 남기고 카테고리 쪽 파트를 붙여요.
- **피드의 파트는 힌트예요.** GQ 코리아 STYLE 피드에 그루밍 기사(각질 관리)가 들어와 menswear로 붙었어요. 3부 파트 배정에서 LLM이 mixed뿐 아니라 모든 기사의 파트를 다시 볼 수 있게 해요.
- `store/sent.jsonl`은 아직 비어 있어요. 6부 publish가 보낸 주소를 쌓기 시작하면 "이미 보냄 N"이 로그에 찍혀요.

## 3부에서 확인한 것 (4·5부 입력)

같은 60건 스냅샷으로 실제 OpenAI(`gpt-4.1-mini`)를 두 번 돌려 PRD 3부 검증표를 봤어요.

| 검사 | 결과 |
|---|---|
| 건수 | 두 번 모두 10건 (👔 3 · 🏃 3 · 🧴 4 / 👔 3 · 🏃 4 · 🧴 3) ✅ |
| 배분 (화장품 1건) | 테스트로 확인: 화장품 1 + 나머지 9건 ✅ |
| 파트 정확도 | 0호 10건 모두 맞는 파트로 배정. GQ STYLE 피드의 각질 기사도 화장품으로 옮겨짐 ✅ |
| 쏠림 | 파트 안 같은 매체 2건 이하, 전체 같은 매체 3건 이하 ✅ |
| 제외 조건 | 연예·경기 결과·딜 기사 0건 ✅ (아모레 먹는 레티놀 출시 보도자료는 1회 통과 — 제품 출시라 경계선) |
| 재현 | 두 실행 공통 9/10 ✅ (기준 8 이상) |
| 0호와 겹침 | 7/10 (사람이 고른 것과 같아야 하는 기준은 아님) |

고치면서 바꾼 것:
1. **기본 몫을 후보가 적은 파트부터 한 건씩 돌아가며 채워요.** 파트별로 몰아 채우니 남성복·스포츠가 GQ 3건을 먼저 써서 화장품의 GQ 기사가 막혔어요.
2. **사건 라벨 대신 `same_as`(같은 사건을 다룬 앞 순위 기사 번호)를 받아요.** LLM이 "남성 그루밍"처럼 뭉뚱그린 라벨을 붙여 다른 기사를 같은 사건으로 지웠고, 하루 8건만 나온 실행이 있었어요.
3. **OpenAI 호출에 `seed`를 고정했어요.** temperature 0만으로는 재현이 6/10까지 떨어졌어요.
4. **`audience.yaml` 기준을 두 줄 더했어요.** "단기간 몸 만들기·과장 제목보다 습관·부상 예방", "쇼핑 목록보다 고르는 기준". 그래도 '28일 식스팩'이 한 번은 결승으로 들어왔어요.

남은 것:
- 스포츠 1위가 GQ "콜레스테롤 식단" 기사예요. 이 기사는 본문에 LDL·HDL을 거꾸로 쓴 문장이 있어서, 5부 verify가 잡아내는지 확인해야 해요.
- 파트 배정이 실행마다 1건쯤 흔들려요(화장품 후보 3 ↔ 4).

## 4부에서 확인한 것 (5부 입력)

3부에서 고른 10건을 실제로 요약했어요. 10건 모두 본문 600자를 넘었고(1,313~6,000자) 세 칸이 한국어로 나왔어요. 영어로 나와 다시 쓴 건은 0건이에요. Permanent Style 기사 페이지도 `requests`로는 정상으로 열렸어요.

요약 속 숫자를 원문에서 직접 찾아봤어요.

| 기사 | 요약 | 원문 | 판정 |
|---|---|---|---|
| 프라다 파라다임 | 8~9시간 지속, 르 파르펭은 1시간 더 | "eight to nine hours", "about an hour longer" | 맞음 |
| Permanent Style | Cutler 캐시미어 £2800, 10선 | "Price: £2800", 항목 10개 | 맞음 |
| 28일 프로그램 | 13파운드 감량, 허리 3인치 | "shed 13 pounds and lost three inches" | 맞음 |
| GQ 각질 | "면도하는 날에는 각질 제거제를 쓰지 않는 것이 좋다" | "면도하지 않는 날에 쓰라 · 아침에 면도하면 밤에 해도 된다" | **조건을 단정으로 바꿈** → 5부가 잡아야 할 사례 |
| GQ 콜레스테롤 | 원문의 LDL·HDL 뒤바뀐 문장은 요약에 안 들어옴 | — | 이번엔 피했지만 5부 검수 기준은 유지 |

5부 시험 세트에 넣을 것: 위 GQ 각질 요약(조건 단정), 숫자를 바꾼 요약, 원문에 없는 제품을 넣은 요약.

선별 쪽 메모: '28일 프로그램' 기사는 Men's Health가 자기 프로그램을 소개하는 글이라 "홍보" 제외 기준에 걸칠 수 있어요.

4부를 끝까지 돌리다 찾은 3부 버그(고침):
- 결승 후보를 파트마다 '남은 자리 수'만큼만 모았는데, 그 후보들이 서로 매체 상한에 막혀 **9건에서 멈췄어요.** 결승이 끝난 뒤에도 자리가 남으면 파트별 순위를 따라 돌아가며 끝까지 채우게 했어요(테스트 추가). 같은 스냅샷으로 세 번 돌려 세 번 모두 10건이 나왔어요.
- 한 번은 "부족: menswear 2/3"이 떴어요. 남성복 후보 9건 대부분이 GQ 코리아라서, GQ가 전체 상한 3건에 걸린 뒤로는 남은 후보가 없었어요. 규칙대로 동작한 거예요. GQ는 피드가 4개라 하루 15건쯤 들어와서, 상한(`max_per_source_total: 3`)을 그대로 둘지는 일주일 지표를 보고 정해요.

## 5부에서 확인한 것 (6부 입력)

검수는 요약을 쓴 호출과 따로 부르고, 제목·요약 두 칸만 원문과 대조해요. 불합격이거나 4부에서 빠진 자리는 3부의 예비 후보(최대 6건)를 자리마다 한 번씩만 취재·검수해서 채워요. 검수 호출이 실패하면 통과시키지 않아요.

4부의 실제 요약 10건과 일부러 틀리게 고친 요약 3건으로 두 번 시험했어요.

| 시험 | 1회차 | 2회차 |
|---|---|---|
| 멀쩡한 요약 10건 통과 | 10/10 | 10/10 |
| 숫자 바꿈 (프라다 8~9시간 → 12시간) | 잡음 | 잡음 |
| 없는 제품 넣음 (니베아 쉐이빙 폼) | 잡음 | 잡음 |
| 원문 오류 옮김 (LDL·HDL 뒤바뀐 문장) | 잡음 | 잡음 |

고치면서 바꾼 것:
- 처음엔 why 칸까지 대조했더니 멀쩡한 요약 2건이 "원문에 40대 언급 없음"으로 떨어졌어요. why는 우리가 덧붙이는 해석이라 대조에서 뺐어요.
- 테스트가 실제 OpenAI를 부르고 있던 걸 발견해서, `tests/conftest.py`로 모든 테스트의 실제 API·네트워크 호출을 기본으로 막았어요.

한계:
- **GQ 각질 요약의 조건 단정은 두 번 다 통과했어요.** 원문은 "면도하지 않는 날에 하라, 아침에 면도하면 밤에 해도 된다"인데 요약은 "면도하는 날엔 하지 말라"고 썼어요. 지시문에 이 예시를 그대로 넣어도 못 잡았어요. 앞부분은 원문 조언과 맞아서 검수 LLM이 '줄여 쓴 것'으로 보는 것 같아요. 4부 요약 지시를 더 다듬거나, 검수도 LLM이라 오판할 수 있다는 한계로 REPORT에 적어요.
- 처음부터 끝까지 실제 실행(dry-run)은 49초, 10건 → 검수 10건이었어요.

## 6부에서 확인한 것 (7부 입력)

- 메시지 4개로 보내요: ① 날짜·오늘 배분 ② 👔 카드 ③ 🏃 카드 ④ 🧴 카드. 기사마다 카드 한 장이라 제목을 누르면 원문으로 가요.
- 실제 요약 10건으로 만든 메시지는 합계 51 · 765 · 1,132 · 767자로 Discord 한도(메시지당 6000자·카드 10장)에 한참 못 미쳐요. 넘치면 가장 긴 요약부터 줄이는 코드와 테스트는 넣어 뒀어요.
- 보낸 날만 `issues/날짜.md`와 `store/sent.jsonl`을 써요. dry-run 사본은 `output/`(git 무시)에 써서 손으로 만든 0호를 덮지 않아요.
- 하나라도 거절되면 `실패`로 적고 보낸 주소는 쌓지 않아요. 로그에 웹훅 주소가 찍히지 않는 것도 테스트로 확인해요.
- 테스트가 진짜 `output/`에 파일을 쓰던 걸 발견해서, conftest가 파일 경로도 임시 폴더로 돌려요.
- 첫 실제 발송 (2026-10-29 오후, 사용자 확인 후): 60건 → 10건(👔 2 · 🏃 4 · 🧴 4, 부족: menswear 2/3) → 검수 10건 → 메시지 4개 **보냄**. 사본 `issues/2026-10-29.md`, `store/sent.jsonl` 10줄.
- 손으로 만든 0호는 첫 발송이 같은 날짜 파일을 쓰기 전에 `issues/0호-2026-10-29.md`로 옮겼어요.
- 7부 입력: `store/sent.jsonl`은 Actions에서 실행이 끝나면 사라져요. 다음 날 중복을 막으려면 Actions가 이 파일과 `issues/`를 저장소에 커밋해야 해요.
- 오늘 이 컴퓨터에서 다시 돌리면 오늘 보낸 10건은 '이미 보냄'으로 빠져요.
